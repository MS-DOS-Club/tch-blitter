# Disassembly of the 68000 code

How the family's game code is obtained and read: one pipeline over **all five games, nine 68000
images** (six main CPUs and three sound CPUs).

The family's 68000 code regions are disassembled and analysed so the boot logic can be reviewed
(`disasm/`, a reproducible pipeline, `make disasm-all`). Detail in
`disasm/README.md`.

What gets versioned is the RELIABLE analysis (recursive, following the real flow): the function map
plus pseudo-C in `disasm/analysis.txt`, one annotated listing per image in `disasm/listings/` (code as
instructions, data as `dc.*`, the known routines and the board's registers named; how to read one
is in `disasm/README.md`) and the memory maps in `disasm/symbols.txt`. The interleaved
images and the Ghidra project are regenerable and go gitignored.

The table is generated from the data: the boot PC comes from bytes 4..8 of the image itself (the
68000's reset vector), the functions from Ghidra's recursive pass (`disasm/analysis.txt`) and the
accesses from `hardware/accesses.yaml`.

The Power Ball and Kong Ball symbols are **propagated from Wheels & Fire** by flow correspondence,
and confirmed one by one by disassembling both windows.

- `radendur`'s boot decompiles to readable pseudo-C: init, a call to the boot initialisation
  (`boot_init`, `0x25dc`) and a main loop with a state machine dispatching screen modes through
  a pointer table (0xf1fd4).
- The **blitter programming** is located (`blit_program` at `0x2004`, the blitter interrupt chain
  at `0x1f2a`, the clear blits of `boot_init` at `0x25dc`, at boot, and `mode_clear_blits` at
  `0x2856`, again from the main loop) and, the blitter sitting at the same address 0x700000 as in
  `rltennis`, the routines of the two boards are directly comparable.

## Wheels & Fire

Its image is built the same way, interleaving `tch1.u19` (odd bytes) and `tch2.u21` (even). The
resulting reset vector is SP `0x201000`, PC `0x0ea3da`.

After `make disasm`, it reads with rizin without needing to re-analyse anything:

```sh
rizin -a m68k -b 32 -qc "e cfg.bigendian=true; s 0xe5300; pd 40" disasm/img/wheelfir_maincpu.bin
```

The game programs the blitter with **absolute writes** to `0x700000`-`0x70001f` (counted in the
table above), a few dozen of them to the trigger. That makes the code directly readable without
following pointers, and it is how the routines annotated in `disasm/symbols.txt` are identified.
